title: Internationalization

A project can have several languages, like fumadocs' i18n. Pages in the
default language are the ones you already have; a translation is a page with
the same slug in another locale.

## Turn it on

In the admin, open the project's **Settings** and set **Languages** to a
comma list such as `en,nl,de`, and the **default** (usually `en`). Or with
the API:

```sh title="terminal"
curl -X PUT https://api.jevidocs.jevido.app/api/admin/projects/my-docs \
  -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" \
  -d '{"name":"My docs","locales":"en,nl","default_locale":"en"}'
```

A project with no languages set behaves exactly as before.

## Write translations

<Tabs items="Files,Admin,MCP">
<Tab value="Files">

Use the fumadocs dot convention next to the original file:

<Files>
<File name="index.md" />
<File name="index.nl.md" />
<Folder name="guides" defaultOpen>
<File name="install.md" />
<File name="install.nl.md" />
</Folder>
</Files>

`jevidocs push`, the GitHub sync and the API's own `content/` all read it.
`page.en.md` (the default locale spelled out) is the same as `page.md`.

</Tab>
<Tab value="Admin">

Create a **new page** with the same slug and set **Locale** to e.g. `nl`.
The page list shows a badge with each page's locale.

</Tab>
<Tab value="MCP">

`read_page` and `search_docs` take an optional `locale` argument.

</Tab>
</Tabs>

## Reading

- URLs of the default language stay as they are (`/p/my-docs/guides/install`);
  other languages get a prefix (`/p/my-docs/nl/guides/install`, or
  `/docs/nl/...` on this site).
- A language switcher appears in the navbar and keeps the current page.
- A page without a translation shows the default-language page with a small
  "not translated yet" note (the API marks it `fallback: true`).
- The sidebar, search, `llms.txt` and the sitemap follow the language: add
  `?locale=nl` to any public read endpoint.
